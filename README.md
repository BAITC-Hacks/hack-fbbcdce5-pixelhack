# EKT AI Assistant — чат и REST API

## 1. Описание

Прототип витрины и консультанта интернет-магазина электротехнической продукции **ekt.kz** для HackAlem AI. Главная страница доступна на `/`, товары загружаются через существующий API-контракт, AI-чат — на `/chat.html`, локальная корзина — на `/cart.html`, API — на `/api/v1`, Swagger — на `/docs`.

Два независимых переключателя позволяют запустить приложение без ключей или подключить реальные сервисы:

| Настройка | Режим | Поведение |
|---|---|---|
| `CATALOG_MODE` | `demo` | Явно синтетические товары, без сети |
| `CATALOG_MODE` | `live` | Read-only API ekt.kz с Basic Auth |
| `ASSISTANT_MODE` | `demo` | Простой детерминированный обработчик демонстрационных запросов, не LLM |
| `ASSISTANT_MODE` | `openai` | Диалог и инструменты через OpenAI Agents SDK |

Корзина **всегда локальная**. В материалах партнёра предоставлены только endpoints списка и карточки товара. Реальный заказ, резерв и корзина сайта ekt.kz не создаются. Возвращаемый `cart_url` ведёт к актуальному JSON локальной корзины и требует Bearer-токен. Это не страница оформления заказа магазина.

## 2. Архитектура

```text
HTML/CSS/JS frontend, Swagger UI
                  |
               FastAPI
                  |
       +----------+-------------+
       |                        |
  AssistantService          REST endpoints
  OpenAI Agents SDK             |
       +----------+-------------+
                  |
       CatalogService / CartService
                  |
     +------------+-------------+
     |                          |
HTTPX -> EKT API        SessionStore (память)
или demo JSON          история, предложения, корзина
```

```text
app/
  main.py                фабрика приложения, lifespan, CORS, ошибки
  api/routes.py          endpoints и авторизация сессий
  core/config.py         Pydantic Settings
  core/errors.py         ошибки предметной области
  schemas.py             контракты запросов и ответов
  integrations/ekt.py    адаптер фактического API партнёра
  services/catalog.py   каталог, поиск, аналоги, условия
  services/cart.py      предложение и подтверждение добавления
  services/sessions.py  ограниченное хранилище сессий с TTL
  services/assistant.py инструменты Agents SDK и offline demo
  services/attachments.py  разбор вложений в памяти
  data/products.json    синтетические данные
front/                  интерфейс чата и локальной корзины
 tests/                  unittest, без внешних запросов
```

Подтверждение — серверное правило, а не только инструкция модели. AI может создать `pending_action`, но не изменить корзину. Frontend показывает товар, цену и количество, затем по нажатию пользователя отправляет `confirmed: true` в endpoint подтверждения. Свободный текст «да, добавь» сам по себе корзину не изменяет.

При подтверждении повторно читаются цена и остаток. Проверяются суммарное количество в корзине, минимальная партия и кратность. Изменение цены возвращает `409`: нужно новое предложение. Повторный запрос с тем же ID не добавляет товар повторно. Запросы одной сессии выполняются под `asyncio.Lock`.

## 3. Стек технологий

Python, FastAPI, Pydantic, Pydantic Settings, HTTPX, OpenAI Agents SDK, Uvicorn, HTML, CSS и браузерный JavaScript без сборщика и frontend-фреймворка. База данных, очереди и векторное хранилище не требуются. DOCX/XLSX разбираются стандартной библиотекой; PDF/JPEG передаются модели. Модель настраивается через `OPENAI_MODEL`.

Интеграция использует [определение агентов и function tools](https://developers.openai.com/api/docs/guides/agents/define-agents), [файловые входы](https://developers.openai.com/api/docs/guides/file-inputs) и [обработку изображений](https://developers.openai.com/api/docs/guides/images-vision) из официальной документации OpenAI.

## 4. Зависимости

- Python **3.11+**, проверено на Python **3.14.0** на Windows и **3.14.7** на macOS.
- Точные версии прямых зависимостей указаны в `requirements.txt`.
- Для установки требуется доступ к PyPI.
- Offline demo после установки не требует сети и API-ключей.
- Для AI нужны ключ OpenAI, доступ к выбранной модели и сеть.
- Для live-каталога нужен доступ партнёра к ekt.kz.
- Node.js не нужен. Тесты используют стандартный `unittest`.

## 5. Переменные окружения

Скопируйте `.env.example` в `.env` **в корне этого репозитория** либо используйте общий `.env` в родительской папке проекта. Приложение читает оба расположения независимо от текущего рабочего каталога; настройки из `.env` репозитория имеют приоритет. Переменные окружения процесса имеют приоритет над файлами. Для настоящей консультации укажите `ASSISTANT_MODE=openai`, `CATALOG_MODE=live`, ключ OpenAI и credentials EKT. Режимы проверяйте через `/api/v1/health`: `demo` означает шаблонный обработчик или синтетический каталог.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CATALOG_MODE` | `demo` | `demo` или `live` |
| `ASSISTANT_MODE` | `demo` | `demo` или `openai` |
| `OPENAI_API_KEY` | пусто | Обязательна для `openai` |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель с tools, для вложений также с поддержкой изображений/PDF |
| `EKT_BASE_URL` | `https://ekt.kz` | Зафиксированный хост партнёра |
| `EKT_USERNAME`, `EKT_PASSWORD` | пусто | Basic Auth из выданного партнёром документа |
| `CORS_ORIGINS` | localhost и 127.0.0.1 на порту 5500 | JSON-массив разрешённых origins frontend |
| `EKT_SEARCH_PAGES` | `5` | До 50 страниц при поиске |
| `REQUEST_TIMEOUT_SECONDS` | `15` | Timeout HTTPX |
| `CHAT_TIMEOUT_SECONDS` | `45` | Общий timeout ответа ассистента |
| `SESSION_TTL_SECONDS` | `3600` | Абсолютный срок жизни сессии |
| `MAX_SESSIONS` | `1000` | Максимум сессий в памяти |

Рабочие секреты не включены в репозиторий. `.env` исключён через `.gitignore`. Для запуска с синтетическим каталогом и настоящим AI достаточно изменить `ASSISTANT_MODE=openai` и заполнить `OPENAI_API_KEY`. Для live-каталога дополнительно задайте `CATALOG_MODE=live` и EKT credentials. При отсутствии обязательного ключа приложение завершает запуск с ошибкой конфигурации, а не переключается незаметно на demo.

## 7. Запуск

Windows:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Linux/macOS:

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте главную: http://127.0.0.1:8000/. AI-чат: http://127.0.0.1:8000/chat.html. Документация: http://127.0.0.1:8000/docs. OpenAPI JSON: http://127.0.0.1:8000/openapi.json. Чат создаёт сессию при открытии и хранит её ID и Bearer-токен только в `sessionStorage`; токен не попадает в URL и не показывается на странице. В demo-режиме примеры запросов относятся к синтетическим артикулам, а загрузка вложений отключена: для неё нужен `ASSISTANT_MODE=openai`.

Используйте **один worker**: сессии и блокировки находятся в памяти процесса. Перезапуск очищает сессии, историю и корзины. `--reload` можно добавить для разработки, учитывая потерю сессий при перезагрузке.

### REST-контракт для frontend

Префикс всех маршрутов — `/api/v1`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | Работоспособность процесса и активные режимы; не проверяет upstream |
| GET | `/products?page=1&q=DEMO-C16` | Каталог/поиск по ID, артикулу и словам названия |
| GET | `/products/{product_id}` | Свежая карточка, цена, остатки, свойства, сертификаты |
| GET | `/products/{product_id}/alternatives` | Аналоги и основания подбора |
| GET | `/purchase-terms` | Известные условия покупки и источник |
| POST | `/sessions` | Создать сессию, получить ID, access_token и срок |
| DELETE | `/sessions/{session_id}` | Удалить сессию и её данные |
| POST | `/sessions/{session_id}/chat` | JSON `{"message":"Есть DEMO-C16?"}` |
| POST | `/sessions/{session_id}/chat/attachment` | Файл в теле запроса, соответствующий Content-Type |
| GET | `/sessions/{session_id}/cart` | Актуальная локальная корзина |
| POST | `/sessions/{session_id}/cart/proposals` | JSON `{"product_id":"demo-1","quantity":"2"}` |
| POST | `/sessions/{session_id}/cart/proposals/{action_id}/confirm` | JSON `{"confirmed":true}` |

Все маршруты конкретной сессии требуют `Authorization: Bearer <access_token>`. ID сессии без токена доступа не даёт. Токен не следует размещать в URL. В Swagger нажмите **Authorize** и вставьте только токен. Денежные значения и количества возвращаются десятичными строками; отсутствующие данные — `null`, неизвестный остаток не превращается в ноль. `fetched_at` — время получения данных.

Ответ чата содержит `message`, `products`, `alternatives`, `pending_action`, `cart`, `assistant_mode`. Frontend отображает текст через `textContent`, а поля карточек отдельно. `pending_action` включает ID, товар, добавляемое количество, цену в карточке и время истечения. У сессии одно активное предложение; следующее заменяет предыдущее. Оно действует 10 минут. После подтверждения UI обновляется из ответа корзины. `cart_url` остаётся защищённым JSON endpoint: UI не открывает его ссылкой, а ведёт на `/cart.html`, которая запрашивает корзину с Bearer-токеном.

Ошибки имеют общий формат:

```json
{"error":{"code":"insufficient_stock","message":"Доступно только 10."}}
```

Основные статусы: `401` — сессия/токен, `404` — товар/предложение, `409` — остаток/кратность/изменение цены, `413` — слишком большой файл, `415` — формат файла, `422` — неверный запрос, `429` — лимит сообщений, `502/504` — сбой/timeout upstream, `503` — исчерпан лимит сессий или AI для вложений не включён.

### Вложения

В режиме `openai` отправьте файл как **raw body**, не `multipart/form-data`. Поддерживаются MIME-типы `application/pdf`, `image/jpeg`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document` и `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`. Максимум 5 МиБ. Предварительный запрос можно отправить обычным сообщением чата; обработка файла учитывает историю сессии.

```javascript
const response = await fetch(`${api}/api/v1/sessions/${sessionId}/chat/attachment`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}`, 'Content-Type': file.type },
  body: file
});
const result = await response.json();
```

Файлы не сохраняются на диск или в историю. Ответ модели остаётся в истории; при повторном анализе самого файла его нужно отправить заново. DOCX — текст абзацев/таблиц; XLSX — значения ячеек, включая сохранённые результаты формул. Формулы и макросы не исполняются. Лимит распакованного архива — 20 МиБ, текста — 20 000 символов. Старые бинарные DOC/XLS, защищённые документы и сложное форматирование не поддерживаются. PDF/JPEG проходят базовую проверку сигнатуры; окончательное распознавание выполняет OpenAI. Не передавайте платёжные реквизиты и ненужные персональные данные.

## 8. Сценарий проверки (Test Flow)

### Интерфейсный Test Flow для эксперта

1. Запустите приложение с `.env.example` и откройте http://127.0.0.1:8000/.
2. Дождитесь статуса «Демо-режим», введите в чат `Покажи шуруповёрт` и отправьте сообщение. В карточке синтетического товара `DEMO-DRILL18` видны фото, артикул, цена, остаток и характеристики. Фото сгенерировано для прототипа и не изображает подтверждённую модель EKT.
3. Введите `Добавь DEMO-DRILL18 2 шт` и отправьте. Появится блок с товаром, количеством, ценой и кнопкой «Подтвердить добавление».
4. До нажатия кнопки откройте «Корзина»: она ещё пуста. Вернитесь в чат, повторите шаг 3, так как переход на страницу корзины перезагружает чат. Фраза `да, добавь`, отправленная в чат, также не добавляет товар и не создаёт вторую кнопку подтверждения.
5. Нажмите «Подтвердить добавление», затем откройте «Корзина». В ней 2 единицы `DEMO-DRILL18` и сумма `49980.00 KZT`.
6. Для ручного варианта у любой карточки укажите количество и нажмите «Подготовить добавление», затем подтвердите отдельной кнопкой. Это не создаёт заказ или резерв на ekt.kz.
7. На ширине около 375 px проверьте, что чат, карточка, предложение и корзина остаются доступны без горизонтальной прокрутки страницы.

### API Test Flow в демо без внешних сервисов

1. Запустите с настройками шаблона `.env.example`, откройте `/docs`.
2. `GET /api/v1/health` → оба режима `demo`, корзина `local`.
3. `GET /api/v1/products/demo-1` → артикул `DEMO-C16`, цена `1500.00`, остаток `10`, характеристики.
4. `GET /api/v1/products/demo-2/alternatives` → `demo-1` с объяснением совпадений. Автомат C32 не предлагается вместо C16.
5. `GET /api/v1/purchase-terms` → содержательные условия, помеченные `source=demo`.
6. `POST /api/v1/sessions` → сохраните `session_id`, вставьте `access_token` в Authorize.
7. `POST /api/v1/sessions/{session_id}/chat`, тело `{"message":"Добавь DEMO-C16 2 шт"}` → `pending_action`, корзина пуста.
8. Отправьте `{"message":"да, добавь"}` в чат → корзина остаётся пустой, API напоминает о явном подтверждении.
9. Скопируйте ID предложения в маршрут `.../cart/proposals/{action_id}/confirm`, отправьте `{"confirmed":true}` → 2 единицы, сумма `3000.00`, `cart_url`.
10. Повторите тот же запрос → по-прежнему 2 единицы. `GET` по `cart_url` с токеном возвращает это состояние.
11. Создайте предложение ещё на 9 единиц → `409`, поскольку в корзине уже 2 при остатке 10.
12. Попробуйте прочитать корзину без токена или с токеном другой сессии → `401`.

### Данные и границы MVP

Контракт партнёра проверен read-only запросами: `/api/products?page=N` возвращает `items`, `page`, `per_page`, `count`; `/api/products/detail?id=ID` — карточку, `quantity`, `stores`, `properties`. Листинг не содержит остатков: API честно возвращает `availability=unknown` до чтения карточки. Basic Auth передаётся только фиксированному HTTPS-хосту ekt.kz; redirects отключены.

Поиск выполняется локально по первым `EKT_SEARCH_PAGES` страницам (по умолчанию примерно 100 товаров). `search_scope` явно показывает область поиска; нулевой результат не означает отсутствие во всём каталоге. Листинг кэшируется 60 секунд, отдельная карточка запрашивается заново. API партнёра не документирует серверный поиск, поэтому его параметры не выдуманы. Следующее расширение — согласованный серверный поиск или полная выгрузка каталога.

Аналоги подбираются консервативно для товаров с указанными полюсами, током, напряжением и отключающей способностью: совпадают все четыре поля и категория, остаток положителен. Проверяются до 10 карточек кандидатов из ограниченной выборки. Для остальных категорий возвращается пустой список с объяснением; эквивалентность для монтажа не гарантируется. В реальном образце описание и свойство номинального тока расходятся — исходные поля сохраняются, ассистенту предписано сообщать о противоречии.

Ссылки сертификатов возвращаются, если присутствуют в поле `certificates`. В проверенной реальной карточке такого поля нет; ссылки не генерируются. В demo сертификатов также нет. Необходим контракт партнёра на сертификаты, если они хранятся иначе. Условия оплаты/доставки в выданных данных отсутствуют: live-режим сообщает об этом и направляет к менеджеру, demo-условия не выдаются за реальные.

История ограничена 20 сообщениями, срок сессии — один час по умолчанию, чат — 10 запросов/минуту на сессию. SDK tracing выключен, запросы модели отправляются с `store=False`; это не отменяет правил обработки данных провайдера. Приложение не логирует тела сообщений и ключи. До публичного размещения нужны авторизация магазина, общий rate limit на входе и HTTPS. Для нескольких workers потребуется общее хранилище сессий и атомарных операций. Интеграция корзины/checkout ekt.kz требует отдельного API и привязки к авторизованному покупателю.

Целевая задержка из ТЗ — несколько секунд; реальная задержка зависит от сети, модели и числа запросов к каталогу и пока не подтверждена нагрузочными измерениями. Живой вызов OpenAI проверен на синтетическом каталоге: цена и остаток, аналог, сертификаты и продолжение диалога. Автоматические проверки используют подменённый Runner; после смены модели или ключа живой сценарий следует повторить.
